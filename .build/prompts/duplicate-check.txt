An issue is a duplicate only if it reports the SAME underlying problem or request: same entity/feature, same symptom, same circumstances. Sharing a topic (e.g. both mention "rates" or "intelligent") is NOT enough. Each candidate shows whether it is open or how it was closed, and the new issue is labelled as a bug report or a feature request.
- Bug reports: a newer report of a problem that an issue "closed as completed" claimed to have fixed is a possible regression, not a duplicate - answer 0 in that case. An issue "closed as not planned" (e.g. a problem outside the integration's control) IS a valid duplicate when it is the same problem, because the same answer applies.
- Feature requests: an earlier request for the same thing IS a duplicate however it was closed - it was either built or declined, and either way the reporter should read that issue.

{"reason": one or two sentences comparing the new issue to the closest candidate, "duplicate_of": the candidate issue number or 0 if none, "why": one plain-English sentence for the reporter naming the shared symptom (e.g. "Both describe the export rate sensors showing unknown after switching to Intelligent Flux") - do not restate the new issue, do not state the cause of either issue as fact, and do not use product, tariff or internal codes, "confidence": 0 to 1}.
